## Atlas Policy

- `statefall-atlas/v1` is a renderer-neutral manifest contract. It permits only relative same-origin asset identifiers below the application base, PNG/WebP MIME, schema/version 1, bounded source dimensions/bytes, unique frame keys, integer in-source nonoverlapping rectangles, positive scale, and normalized anchors.
- The isolated development Pixi registry atomically stages decode, base texture, and every subtexture before publication. Fetch, HTTP, MIME, byte, decode, dimension, manifest, texture, or cap failure destroys staging and invokes complete caller-selected Canvas fallback. Atlas refcounts prevent live eviction; deterministic zero-reference LRU, reset, context reset, and destroy release base/subtextures and decoded sources.
- Default caps are 8 live atlases, 4,096 frames per atlas, 4,096 x 4,096 source dimensions, 32 MiB per source, and 64 MiB total source bytes. Diagnostics separate manifests, atlas textures, subtextures, generated textures, label textures, references, source bytes, loads, fallbacks, evictions, and destruction. Production bundle reporting separately inventories atlas manifests/textures, fonts, and audio.
- A synthetic 8 x 4 same-origin/test Canvas source creates actual red/blue Pixi subtextures at effective DPR 1, 1.5, and 2, verifies scale/anchor metadata and pixels, then reaches zero atlases/frames/references/source bytes on context reset. No authored art was added.
- E migration art stays in its existing bounded generated/vector/raster registries. It is not forced into a dynamic atlas. Every authored atlas and unit visual belongs to Phase G and must pass `docs/unit-art-review.md` with named human approval.
