## E3 Implemented Slice

- Added a pure renderer-neutral pre-structure scene model. It consumes detached presentation, camera, viewport, quality, reduced-motion, and supplied presentation-time values; it imports no Pixi, DOM, timer, or simulation authority.
- The model preserves legacy order and meaning for attack-front tile pulses; supply links and gold markers; missile focus; command, flight-operations, and troop-command links/markers; airfield and shield bubbles; shield/gun/health pips; repair arcs; and jammer, gun, missile-command, SAM, and fort ranges.
- In safe scenes Pixi owns two persistent global `Graphics` objects ordered `fronts`, `routes`. A bounded tile-keyed pool supplies one pre-base `Graphics` plus one base `Sprite` per needed structure entry; entries are appended in legacy structure-array order. No object is allocated per primitive, and no new art was introduced.
- Canvas retains every post-base primitive: building, upgrade, air/ship queue, and cooldown progress; countdown and queue text; pop rings; level marks; suppressed X; linked circles; all transports, ships, aircraft, missiles, shells, effects, labels, alerts, selection, and input.
- The model uses stroke-width/radius-aware geometric culling, including line-versus-expanded-viewport intersection, and enforces hard frame limits of 65,536 conceptual primitives and 131,072 emitted Graphics path segments. One exported structure-base helper is used by viewport culling, conflict detection, diagnostics, and tests: painted extent is `max(r + max(1.5, 0.18r) / 2, typeExtent) + max(1, r / 24) CSS px`. The first term is `drawIcon`'s outer circle plus half its line width; the final term is a conservative one-pixel antialias margin that scales when the radius-24 generated texture is enlarged. The icon-primitive audit found two glyph overhangs: engineering command's hook uses `typeExtent=1.13r`, Bertha's muzzle flare uses `typeExtent=1.12r`, and all others remain inside the outer circle stroke with `typeExtent=r`. The 4,096 live/512 idle entry cap accounts for both a `Graphics` and `Sprite` per entry; the texture cap remains 512.
- A shared pure generator produces immutable path-segment arrays for lines, phase-shifted dashes, circles, arcs, and rectangles. Model accounting is exactly the sum of those arrays and Pixi consumes those same arrays without re-segmenting; quality scales route dash/gap lengths once. A frame at the cap is accepted, and cap plus one is rejected before any drawing.
- Ownership is transactional. Model, primitive, segment, Graphics, entry, sprite, texture, or source failure clears pre-layers and bases before returning false, and the calling render pass restores the complete Canvas legacy sequence synchronously.
- Split canvases cannot reproduce arbitrary global structure-array order while post-base overlays remain on the upper Canvas. Before ownership, E3 conservatively bounds building/upgrade/air/ship queue rings and text, pop rings, level marks, suppressed X marks, linked rings, cooldown rings, every other retained post-base mark, and every later Pixi pre-base primitive/range/base. Any possible earlier-Canvas/later-Pixi overlap atomically clears active Pixi entries and renders all pre-structure and structure work through Canvas for that frame. It is diagnosed as `compositingConflictFallback`, not culling or a resource cap, and the next safe frame retries.
- E3 therefore preserves legacy ordering through Pixi when safe and through synchronous full-Canvas fallback when split-canvas order could differ. It does not claim unconditional Pixi ordering or a closed migration. The eventual fix is migration of all structure post overlays or a unified scene graph.

## Quality And Motion

- Renderer-neutral quality is `high|medium|low`. Source proof defaults to high. Query control is accepted only by the development renderer factory while the guarded browser test bridge is active; production has neither the switch nor the Pixi graph.
- Quality changes route dash density/segment count only. Every frontier, route marker, focus ring, command link, target/range circle, status bubble, and gameplay pip remains represented.
- The renderer/controller supplies one effective pre-structure motion state per frame. Normal motion uses monotonic presentation time. Reduced motion supplies fixed time `0`; markers remain at their defined midpoint, front alpha remains `0.5`, low-shield alpha remains `0.14`, and route plus missile-focus dash phase remains `0`. Canvas default, conflict/resource fallback, and Pixi use the same state. Unrelated later UI/effect clocks are intentionally unchanged. No route, target focus, status, or range information is removed.
- Missile focus no longer depends on inherited Canvas context state: supply, command, and focus strokes all explicitly use route phase `(effectiveTime / 60) % 16`, represented as Canvas `lineDashOffset=-phase` and the equivalent generated Pixi segment phase.
- Diagnostics expose requested/effective quality, reduced motion and effective clock mode, structure painted bounds, global and per-entry Graphics/Sprite counts, exact entry order, semantic and emitted-segment counts/maxima, generated presentation samples, ownership, bounded resource failure count/reason, and a separate compositing-conflict count/reason/detail.

## Safety And Compatibility

- Default Canvas executes the original drawing statements and retains its authoritative screenshot baselines. In Pixi mode each legacy block is skipped only on complete safe pre-layer/structure ownership; conflict fallback executes the entire original sequence with no duplicate pre-base pixels.
- Camera coordinates remain shared CSS pixels. Canvas and Pixi backing stores use the same DPR-capped viewport, preserving base/overlay/target alignment at DPR 1, 1.5, and 2 through pan, zoom, resize, fallback, and return.
- Plugin 1.10.7 and `SIMULATION_BASELINE_VERSION='1.10.8'` are unchanged. Rendering does not mutate canonical bytes, hash, simulation RNG, command log, replay cursor, or tick.
- Context loss still falls back to the complete Canvas renderer. Reset, BFCache recreation, new maps, panning, cap exhaustion, and source failure clear/reuse bounded resources without retaining stale ownership.
- Production uses the replacement Canvas factory and has no selectable/reachable Pixi renderer or Pixi JavaScript chunk.
