_Development record through game/package 1.10.19, build `2026-09-18-phase-e7-pixi-projectiles`, on 18 September 2026. E6 is `7cd64f4`. This is not a release, handoff, production change, Phase E completion, or final-art approval._

## E7 Implemented Slice

- Migrated exactly the contiguous legacy `shells` block and immediately following `visualShots` block after warships and before strategic/cruise missiles. Torpedo foam/body, AAM trail/body, arcing barrage rocket/trail, arcing artillery shell/ground tether, ordinary gun-shell trail/body, and short visual gun lines preserve shell-array then visual-shot-array order and exact branch primitive order. Strategic/cruise missiles, main aircraft, and all later world layers remain on transparent Canvas above Pixi.
- The pure renderer-neutral model consumes detached stepped shell coordinates, explicit fog visibility, height-bearing trails, camera/viewport state, and E6's inherited stroke state. It preserves legacy rise/arc/total fallback, delay metadata, colors, alpha, widths, dash, cap, and join chronology without writing shells, trails, ages, or totals. WeakMap object identities plus deterministic occurrence suffixes cover non-ID objects; removed renderer fallback totals clean deterministically.
- Visual shots now advance once per displayed frame through a backend-neutral update that emits immutable age/alpha/lifetime descriptors and a replacement presentation list. Canvas and Pixi consume the same descriptor set, so Pixi rejection, same-frame Canvas fallback, and later retry cannot double-age or fallback-age a line. Reset/restart clears presentation and renderer state.
- Hard reject-not-truncate limits cover 8,192 entries/containers, 262,144 trail points, 262,144 primitives, 524,288 generated segments, and 32,768 Graphics resources. Idle pools are bounded at 1,024 containers and 4,096 Graphics. Conservative AA/stroke bounds include all trails, elevated arcs/bodies, tethers, foam points, and crossing gun lines; an offscreen center does not cull crossing geometry.
- Ownership requires complete structures, naval logistics, and warships in the same frame. Model, cap, container, Graphics, paint, append, prerequisite, or context failure withdraws every shell and visual shot, retains valid Pixi warships, paints the complete Canvas projectile block immediately after them, and retries on the next valid frame. Resources reserve before attachment and dirty partials are discarded. The exact resulting Canvas state is handed to retained missiles, which remain above both backends.
- A fatal final Pixi submission failure is different from a rejected individual layer: the controller synchronously destroys Pixi, installs Canvas, retains the bounded failure reason, and asks the caller to repaint the entire presentation frame once. The repaint clears first and reuses one frame token, timestamp, visual-shot descriptors, and prepared label positions. The focused probe fingerprints the observable presentation fields listed below and verifies a single advance; it does not claim coverage of unobserved browser or Pixi internals. This terminal policy intentionally stays on Canvas until reload or another explicit lifecycle initialization; it does not retry Pixi recursively.

## E6 Implemented Slice

- Migrated exactly the contiguous warship/submarine block after boarding and before shells. All eight classes retain legacy warship-array order and per-entry range, selection/destination, wake, hull/detail/HP, muzzle, refit, CM, and cooldown order. Shells/projectiles and every later layer remain on the transparent Canvas above Pixi.
- The pure renderer-neutral model receives interpolated presentation coordinates and explicit legacy fog/sub-detection results. Stable positive simulation IDs are mandatory and unique; reorder/removal/re-add uses those IDs and duplicate or missing IDs withdraw the complete layer instead of cross-wiring records. Renderer presentation lean state remains keyed by the same ID and updates at most once per visible actor per frame without simulation writes.
- Class radii, colors, destination rules, surface wake formulas, submarine hull/muzzle alpha scope, tick-derived turn lean and recoil/fire angle, class details, ceil HP pips, refit/cooldown fractions, and the CM canvas-raster alphabetic baseline are represented by bounded vector/raster primitives. This is migration art, not final art, and no hull texture atlas was introduced.
- Warships consume the exact E5 Canvas cap and advance it chronologically through fog-visible entries in warship-array order. Owned ranges and selection/destination use each entry's incoming cap; a surface wake with at least two points then changes the global cap to round before that ship's hull/details/statuses, even when the wake geometry is viewport-culled. A shorter surface wake and every submarine leave the cap unchanged, so submarines and later ships inherit prior actors' state. `drawShip` scopes only a round join with save/restore: closed hull outlines use that join while open mast/gun/detail lines retain the current cap. Refit/cooldown and the final retained-Canvas handoff use the resulting cap without retroactively changing earlier primitives; fog-hidden wakes do not transition it. The handoff also restores global alpha 1, empty dash, and zero offset.
- Hard reject-not-truncate caps cover 4,096 entries/containers, 131,072 wake points, 131,072 primitives, 262,144 emitted segments, 16,384 Graphics resources, and 4,096 raster labels. Idle pools are bounded at 512 containers, 2,048 Graphics, and 512 labels. Bounds include ranges, destinations, wakes, muzzle flashes, hull/HP, and status arcs/labels; crossing lines and circles survive center culling.
- Ownership is transactional. Warships can be Pixi-owned only when complete structures and naval logistics are both Pixi-owned in that frame. Resources reserve before attachment. Model/cap/container/Graphics/label/source/context failure discards dirty partials, withdraws every warship, and paints the complete Canvas warship block after valid Pixi naval logistics in the same frame. A valid later frame retries; retained Canvas shells remain above either path.
