## E2 Implemented Slice

- Extended the renderer-neutral controller with `updateWorldLayer()` and capability/ownership diagnostics. Canvas implements a no-op structure layer and reports `structures:false`; healthy `pixi-hybrid` reports `structures:true` and owns a dedicated `structures` container under the planned entity container.
- Pixi owns structure base icons only. The existing Canvas loop still draws all shield, health, repair, range, command-link, build, upgrade, queue, level, linked, cooldown, suppression, pop-ring, and text overlays in the same iteration/order. Its two existing `drawIcon` calls are skipped only while the active renderer confirms structure ownership. Building progress/text and its `continue` behavior are unchanged.
- Structure textures are generated by an injected callback that calls the existing `drawIcon` Canvas routine. No icon paths or art were copied. Registry identity includes structure type and normalized owner color. Sources are validated, sampled linearly for readable arbitrary CSS-pixel scaling, counted with a byte estimate, and destroyed with textures on reset, renderer destruction, failed restore, or context-loss fallback.
- Structure sprite identity is the stable structure tile, never array position. Existing sprites remain attached to their tile while visible. Removed, fogged, below-cutoff, or offscreen structures return to a bounded pool and are reused in current structure iteration order.
- The hard resource limits are 4,096 total allocated structure sprites, including at most 512 idle pooled sprites, and 512 generated structure textures. Texture eviction considers only unreferenced entries, so an active sprite never retains a destroyed texture. A frame pre-reserves every missing sprite; sprite-cap, texture-cap, resource, or invalid-source failure releases every active structure base and returns false ownership before the Canvas base pass. Diagnostics expose true geometric culling separately from `resourceLimitFallback` count/reason, active ownership, bounded instances, and texture allocation/destruction evidence. Later frames retry and resume Pixi only when the complete visible set can be acquired.
- Position and size use the shared CSS-pixel camera: tile center, legacy `r=max(6,s*2.4)`, cutoff `s>=0.9`, legacy building alpha `0.45`, and legacy pop scale. Fog tests use the same render visibility buffer. Viewport culling includes the icon/pop margin.
- Whole-renderer failures still mark Pixi unhealthy before controller fallback. Structure resource exhaustion is narrower: the terrain renderer remains healthy while structure ownership becomes false for that frame and Canvas draws every base atomically. Context/init/render failures continue through the existing idempotent Canvas fallback lifecycle without simulation restart.
- Hybrid compositing has one explicit E2 residual. Legacy Canvas draws attack fronts and supply/command lines before structure bases, while the split canvases place all Pixi bases beneath those Canvas marks. Focused semantic/pixel coverage pins the difference. Moving the Pixi structure canvas above Canvas would incorrectly cover status overlays and later Canvas entities, so ordering is deferred until route/front layers move rather than introducing duplicate base drawing.

## Safety Boundary

- The renderer receives detached presentation descriptions only. Structure rendering cannot issue commands or mutate authoritative state. Canvas remains the sole input surface.
- Vite replaces the development renderer factory for production. The production module graph has no renderer switch, Pixi import, Pixi JavaScript chunk, or browser test bridge. Shared inert `.pixi-*` CSS selectors remain allowed.
- Plugin 1.10.7 and `SIMULATION_BASELINE_VERSION='1.10.8'` are unchanged. No simulation or Canvas golden baseline is intentionally changed by E2.
- Context loss deliberately falls back to Canvas rather than attempting in-place WebGL recovery. BFCache recreation rebuilds texture/sprite resources from the next presentation update without retaining old sources.
